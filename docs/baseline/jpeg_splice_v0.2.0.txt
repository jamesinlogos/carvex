JPEG splice acceptance baseline (H-18 step 0 / conflict C1)
=========================================================

Protocol: harness.md §6.2 H-18(0). The script
`scripts/jpeg_splice_property.py` generated 50 distinct images per content
class (noise, gradient+noise, photo-like from `bench/corpus/jpeg`), saved each
as baseline and progressive JPEG, and evaluated 1,000 independent pairs with
cuts aligned to 512 or 4096 bytes inside 10-90% of the shorter file. A splice
counts as accepted when an emitted output has `validation=decoded` and a
SHA-256 that matches neither input. Wilson intervals are 95%.

The remaining accepted cases are byte-aligned tail swaps between baseline
JPEGs with identical SOF/quantisation/Huffman headers. Each is a self-consistent
Huffman bitstream that passes the implemented RSTn (when DRI is present), MCU
count against SOF geometry, and exact EOI-consumption checks. No detector that
rejects these cases while preserving clean baseline JPEG labels was found;
adding a heuristic would require tuning against the measurement corpus. Per
D-45 the point estimate and 95% CI are recorded as-is and the residual accepted
cases are disclosed rather than hidden by a false-positive-prone rule.
